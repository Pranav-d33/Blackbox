Verify before actuate

It only moves on what 0G signed.

Most systems log what the AI said after the fact. Blackbox puts the check in the control loop. A dishonest operator can't make the robot act on a decision 0G never made, and can't flip a real one.

Why 0G

Three layers.
Each doing real work.

A signed log alone doesn't need a blockchain. Proving which sealed model made each call, and that the robot obeyed only it, does.

0G Compute

The model signs its own answer.

Sealed inference in an Intel TDX enclave. The signer is registered on 0G, so anyone can tell which model made the call.

0G Storage

Every decision, by root hash.

Crop hash, answer, request id and TEE signature, signed by the robot and chained.

0G Chain

Anchored every two decisions.

The mission and its policy are registered before takeoff. Change one entry later and the verifier names it.

zerobot

A robot with an identity.

Only a registered zerobot operator key can anchor its missions.

Fails closed

No answer, no motion.

0

decisions faked when 0G is unreachable. There is no fallback model.

For developers

Built for any robot.

A mission profile is a small JSON task pack: the world, the labels 0G may answer, the actions it may choose, and the prompt. It goes on 0G Storage with the manifest, and the robot's interlock enforces it. Implement three calls and your robot runs under Blackbox.
