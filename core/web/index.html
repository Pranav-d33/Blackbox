Loading the last mission…

An inspection drone makes calls that cost money. Today the only record is the operator's own database. Blackbox has 0G's sealed model make each call, and the robot refuses to move on anything else.

One checkpoint

  1. It holds.

    The detector flags a mark on a module. It never decides. The drone stops in the air and seals a nonce to this exact frame.

  2. It asks 0G.

    The crop goes to 0G's own vision model, running sealed in an Intel TDX enclave. No chat, no avatar. Just strict JSON back.

  3. 0G answers. And signs.

    The answer echoes the nonce, so it was made for this request. The enclave signs the exact response bytes.

  4. The robot checks.

    Four checks, on the robot itself, before a rotor changes speed. Any failure is a refusal. Never a default.

  5. Then it acts. And remembers.

    A robot-signed, hash-chained entry goes to 0G Storage. Every two decisions, the chain head is anchored on 0G Chain.

The party running the drone has the most reason to edit the record. So every attack they can try, Blackbox catches.

Forged decision

A fake "continue." Refused.

Why 0G

Three layers.
Each doing real work.

A signed log alone doesn't need a blockchain. Proving which sealed model made each call, and that the robot obeyed only it, does.

0G Compute

The model signs its own answer.

Sealed inference in an Intel TDX enclave. The signer is registered on 0G, so anyone can tell which model made the call.

For developers

Any robot.
Three calls.

A mission profile is a small JSON task pack: the world, the labels 0G may answer, the actions it may choose, and the prompt. It goes on 0G Storage with the manifest, and the robot's interlock enforces it.
